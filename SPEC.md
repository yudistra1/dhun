# Dhun — Product Spec (v0.1)

> An original, open desktop DAW inspired by pattern-based workflows.
> Clean-room: no FL Studio (or any other DAW) code, UI assets, icons, presets, samples, or branding.
> Owner: Saathwik Godela

---

## 1. Goal of v0.1

**"Make a beat and record a riff."**
A user can open Dhun, program a drum pattern, write a melody in a piano roll, record a guitar take from a USB audio interface, mix it, save the project, and export a WAV.

## 2. Target user & environment

- macOS (Apple Silicon) first; code should stay cross-platform (Windows/Linux later).
- Input: USB audio device (e.g. a guitar amp with USB audio out). Output: system default or chosen device.
- Sample rates: 44.1 kHz and 48 kHz. Buffer sizes: 64–1024 frames.

## 3. In scope (v0.1)

### 3.1 Transport
- Play / stop / return to start, loop on/off with loop range.
- Tempo 40–240 BPM (default 120), 4/4 only.
- Metronome on/off, with count-in (1 bar) when recording.
- Timing resolution: 960 PPQ internally.

### 3.2 Step sequencer (patterns)
- Pattern = grid of channels × 16 steps (configurable 8/16/32), per-step velocity.
- Built-in **synthesized drum kit** (kick, snare, clap, closed hat, open hat, tom). All sounds are generated by Dhun's own DSP — no third-party samples.
- Multiple patterns; a simple song arrangement = ordered list of patterns (playlist v0: linear sequence, no overlapping clips).

### 3.3 Piano roll
- Per-channel note editing: add, delete, move, resize, velocity.
- Snap: 1/4, 1/8, 1/16, 1/32, off.
- Instrument: **built-in subtractive synth** — 2 oscillators (sine/saw/square/triangle), detune, low-pass filter (cutoff/resonance), ADSR amp envelope, 8-voice polyphony.

### 3.4 Audio tracks
- Arm a track, choose input device + channel, record with count-in.
- Input monitoring on/off.
- Recorded takes saved as WAV files in the project folder; latency-compensated on placement.
- Basic clip editing: move, trim start/end.

### 3.5 Mixer
- One mixer channel per sequencer channel / audio track, plus master.
- Volume (dB), pan, mute, solo.
- Peak meters per channel and master (post-fader), clip indicator.
- Built-in effects on master and channel inserts (v0.1 minimum): **gain, 3-band EQ, simple compressor, reverb**.

### 3.6 Project & export
- Project = folder containing `project.json` (+ `audio/` for recordings).
- Versioned project format (`format_version` field) with forward migration hooks.
- Autosave every 60 s to a backup file.
- Export full song or loop range to WAV (16/24-bit, 44.1/48 kHz). Export is **offline and deterministic** (same project → bit-identical output).

### 3.7 Headless CLI
- `dhun render <project> -o out.wav [--range a:b]` — offline render.
- `dhun info <project>` — print project summary.
- `dhun validate <project>` — check project file integrity.
- Every feature added to the engine should be reachable from the CLI where it makes sense — this is how agents test without a GUI.

## 4. Out of scope (v0.1)

VST3/CLAP/AU plugin hosting, automation lanes, MIDI hardware input, time-stretching/pitch-shifting, sidechain, multiple time signatures, overlapping playlist clips, undo history beyond a simple stack, cloud features.
(Planned: v0.2 MIDI input + automation; v0.3 CLAP plugin hosting.)

## 5. Non-functional requirements

| Area | Requirement |
|---|---|
| Real-time safety | Zero allocations, locks, file I/O, or logging on the audio thread |
| Dropouts | No underruns at 256-frame buffer with 16 channels + master FX on Apple Silicon |
| Latency | Round-trip latency reported to user; recordings auto-compensated |
| Determinism | Offline render of the same project is bit-identical across runs |
| Stability | Malformed project files never crash the app — they return clear errors |
| UI | 60 fps UI; UI never blocks the audio engine |

## 6. Architecture (layered — enforced)

```
dhun-core     shared types: time (ticks/samples), tempo map, ids, errors     (no deps on other crates)
dhun-dsp      oscillators, envelopes, filters, drum synth, effects           (depends on core)
dhun-project  project model, serialization, migrations                       (depends on core)
dhun-engine   audio graph, voices, scheduling, recording, offline render     (depends on core, dsp, project)
dhun-io       real-time audio device I/O (cpal)                              (depends on core, engine)
dhun-cli      headless commands                                              (depends on engine, project)
dhun-ui       egui views: sequencer, piano roll, mixer, transport            (depends on project; talks to engine only via messages)
dhun-app      binary: wires ui + engine + io                                 (top layer)
```

Rules:
- Lower layers never depend on higher layers.
- UI ↔ engine communication only via lock-free message queues (commands in, state snapshots/meters out).
- All DSP is pure and unit-testable without an audio device.

## 7. Suggested crates (agents may propose alternatives with justification)

`cpal` (audio I/O), `eframe/egui` (UI), `hound` (WAV), `serde` + `serde_json` (project), `rtrb` (lock-free ring buffer), `thiserror` / `anyhow` (errors), `clap` (CLI).

## 8. Acceptance tests for v0.1

1. **Golden renders:** a set of reference projects in `tests/fixtures/` render to WAVs that match stored golden files (exact match, or within a documented tolerance where floating-point allows).
2. **DSP unit tests:** oscillator frequency accuracy, filter response at known points, envelope timing, no NaN/inf output, no DC offset beyond tolerance.
3. **Round-trip:** save → load → save produces an identical `project.json`.
4. **Fuzz/robustness:** corrupted or truncated project files return errors, never panic.
5. **Real-time audit:** a test/allocator guard proving the audio callback path does not allocate.
6. **Performance:** benchmark render of the 16-channel stress project faster than 10× real-time offline.
7. **Manual check (human):** record 30 s of guitar from the USB interface, line it up with the beat, export, and listen.
